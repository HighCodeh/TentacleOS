# RF laboratory update — 25 November 2026

This update targets `lab/rf`, starting from published commit `5af4fea`.
It collects the pending RF laboratory work and the CC1101/Sub-GHz changes into
separate commits. It does not merge current `dev`, move microphone/NFC pins
between the P4 and C5, or include the USB Host mouse and battery experiments
from the integrated working copy. The earlier NFC MCU_CLK discussion is a
hardware proposal, not an implemented feature in this firmware.

The publication contains 20 commits: 14 pending RF laboratory commits, followed
by six commits separating the current driver, protocol, receiver/UI, diagnostics,
analyzer and documentation work. Each new commit explains its behavior and
validation in the commit body.

## Changes and reasons

| Area | Problem addressed | Result and canonical documentation |
| --- | --- | --- |
| RF ownership | Failed startup/cleanup could leave competing radio workflows or an incorrect success indication. | Checked radio states, bounded waits and ownership retained until cleanup succeeds. [Sub-GHz lifecycle](../SubGhz/README.md#receiver-subghz_receiver). |
| RF matching | The four switch states were difficult to identify and compare. | Illustrated branch/inductor diagram, GPIO readback and explicit branch selection. These are matching branches on one antenna feed. [RF controls](passive.md). |
| CC1101 modem | Shared/generic modem settings differed from the named Flipper presets; upper-band PA step indices were shifted. | Explicit OOK270/OOK650 and FSK profiles, corrected 868/915 PA indexing, checked tuning and per-board paths. [Register tables](../cc1101/README.md). |
| Protocol capture/replay | Partial PWM frames could be accepted; timing and replay metadata were lost or inconsistent. | Complete Princeton/Nice Flo boundaries, RCSwitch framing, persisted timing/repeats and checked native/RAW replay. [Known-code verification](../SubGhz/README.md#known-code-bench-verification). |
| Read / Read RAW | Capture state, sampled signal strength and file results were difficult to inspect. | Live RSSI/history, bounded pulse preview, explicit Save/Send/Again, editable names and non-overwriting storage. Newest files remain visible in large directories. [Receiver view](../SubGhz/README.md#receiver-subghz_receiver). |
| Frequency discovery | The previous menu spectrum was fixed around one frequency. | Receive-only Auto/315/433/868/915/Full searches, refinement, threshold controls, pause and RAW handoff. [Analyzer](../frequency_analyzer/README.md). |
| LF RFID diagnostics | Reader drive, load modulation and unqualified feedback were conflated. | GPIO2 carrier / GPIO11 load roles, timestamped DA decoding, bounded waveform tests and GPIO16 sampled-voltage diagnostics. [RF frontend](../rf_frontend/README.md). |
| Lab access | Oscilloscope tests required repeated GUI interaction. | Explicit UART/scope commands and a separate standalone RFID bench target. [Terminal instructions](../hardware_lab/RFID_UART.md). |

The RF-focused P4 build omits games to fit the laboratory workflow. It retains
the existing lab boot/passive policy. Production `dev` is not updated by this
publication. C5 firmware and paired protocol definitions are unchanged.

## Device workflow

1. Open **Sub-GHz > Config** and select the frequency and modem preset. This lab
   profile initially selects **315 MHz / OOK270**; that is a default, not an
   automatic transmission or a guarantee that every 315 MHz remote uses OOK.
2. Use **Read** for supported protocol decoding or **Read RAW** for signed pulse
   durations. A capture stops reception and displays its result. **Send** is an
   explicit action; a successful reception never automatically transmits.
3. Use **Frequency Analyzer** to search for a repeated/held signal. LEFT/RIGHT
   changes bands, UP/DOWN changes the threshold, OK pauses, and BACK exits.
   While paused, select **Read RAW** to use the detected frequency after cleanup.
4. Use **RF Lab** for manual matching-branch comparison, passive measurements and
   bounded active tag searches. Follow the [mode-specific controls](passive.md);
   GPIO readback alone is not proof of RF output or matching quality.

The analyzer is experimental: acquisition is still slow on the observed unit.
A visually refreshed RSSI bar does not mean a complete frequency sweep occurred
at the same rate. Short bursts can be missed while another channel is selected.

## Terminal quick reference

Run one RF operation at a time. Query status and wait for checked cleanup before
starting the next operation. These commands are sent to the High Boy console,
not to the computer shell.

```text
rfbench info
rfbench status
cc1101 status
subghz rx 315000000 10 raw ook270
subghz rx 433920000 10 ook270
subghz list
subghz analyzer
cc1101 stop
rfbench stop
```

`subghz analyzer` reports an already opened analyzer session; it does not start
one. RSSI values are receiver estimates, and `samples`/`sweeps` are not packet
delivery counts. Check `error`, `sweep_us` and `refine_us` as well as frequency.

For a controlled known-code bench test, with the independent receiver ready:

```text
cc1101 txtest ARMED 5AA55A 0 433920000
```

This sends five synthetic RCSwitch P1 frames. Supported explicit power arguments
are 0, 5 and 10 dBm nominal, and this command accepts 433920000 or 868350000 Hz.
Repeat with independent test codes when checking complete payload decoding.
Actual radiated power is not established by the programmed PA value.
The generic [RF chamber commands](README.md#commands) have a different packet
format and are not an interchangeable test of remote-control protocol replay.

LF examples, with the scope/tag arrangement appropriate to the selected mode:

```text
rfid status
rfid read 5000
rfid voltage passive 500
rfid off
```

The voltage diagnostic samples GPIO16 through the ADC; it does not replace a
scope or prove a valid digital-high level. It restores the digital input and
reports cleanup failures. The proposed NFC MCU_CLK connection is not part of
these LF commands.

## Validation and evidence boundaries

The scoped P4 application and assets build passed using the pinned ESP-IDF v6.1
environment. The application is 2,847,280 bytes (`0x2b7230`) in a 3 MiB slot,
leaving 298,448 bytes (9%) free. Paired SPI/transport and architecture contracts
passed. The build retains an existing `beacon_spam_start_custom` string-bound
warning outside the RF changes; it is not a warning-free build.

The separate `firmware_lab_rfid` UART target also built successfully against the
same SDK. Eighteen focused host test entry points passed after commit formatting,
along with the independent LVGL fixture and the Sub-GHz, RF bench and analyzer
UI suites. No C5 firmware change is included.

Host validation covers the production driver/worker logic with hardware fakes:
SPI failures, synthesizer deadlines, channel ownership, cancellation, late RX
callbacks, repeat framing, full RAW storage, filename collisions and file ordering.
Analyzer tests cover band gaps, four synthetic carriers, off-grid refinement,
noise/transient rejection and failures at every radio-call position. These are
software tests, not measurements of RF sensitivity, transmit power or range.

Real LVGL host rendering covers 240x320 and 320x240, light/dark themes, controls,
RAW handoff, error cleanup and the RF switch screen. It checks layout and UI
behavior, not display DMA or touch behavior on the physical device.

Reproduce the focused checks from the repository root with ESP-IDF v6.1 and the
dependencies described in [build setup](../highboy/README.md#build):

```sh
bash tools/build.sh p4
python3 tools/highboy/check_contracts.py
python3 tools/highboy/test_subghz.py
python3 tools/highboy/test_subghz_lifecycle.py
python3 tools/subghz_api/test_subghz_api.py
python3 tools/highboy/test_cc1101_console.py
python3 tools/frequency_analyzer/test_frequency.py
python3 tools/hardware_lab/test_lf_reader.py
python3 tools/hardware_lab/test_lf_voltage.py
python3 tools/rf_chamber/test_bench.py
python3 tools/rf_chamber/test_tag_scan.py
```

The macOS publication run uses `HIGHBOY_TEST_SANITIZERS=undefined` for the RX
lifecycle and Sub-GHz API harnesses. The normal default remains AddressSanitizer
plus UBSan. A trivial AddressSanitizer program also timed out on this host, so
this run does not claim ASan coverage. Re-run the default on a working ASan host.

To generate an independent LVGL host build and the analyzer screenshots:

```sh
python3 tools/highboy/tests/test_keyboard_ui.py /tmp/highboy-rf-ui
python3 tools/highboy/tests/test_ux_flows.py /tmp/highboy-rf-ui
python3 tools/rf_chamber/test_bench_ui.py /tmp/highboy-rf-ui
python3 tools/frequency_analyzer/test_ui.py --host-build /tmp/highboy-rf-ui --output /tmp/highboy-rf-ui/analyzer
```

The normal test entry points also register the new analyzer, console and voltage
checks. The LVGL fixture enables the same 24-pixel frequency font as the P4 build.

Historical hardware observations are recorded in the [CC1101 matching
section](../cc1101/README.md#high-boy-v203-matching-network) and the
[analyzer validation section](../frequency_analyzer/README.md#validation).
They were taken on earlier integrated images, not this newly scoped publication.
No device is flashed and no RF transmission is performed by the publication
checks above.

## Remaining acceptance work

- Measure analyzer scan/calibration/SPI/scheduling latency with fixed settings;
  compare repeated known-transmitter acquisitions, not UI animation speed.
- Repeat complete-code capture and saved-file replay in both directions at each
  qualified band, using the same distance, orientation and matching branch.
- Measure conducted output and sensitivity, then over-the-air performance.
  The prototype switch map is not a universal result for every assembled unit.
- Confirm LF electrical levels and repeated reads of a known physical tag.
  Timestamp decoding and an ADC diagnostic do not establish a repaired frontend.
- Check on-device navigation, display updates and RF cleanup on this exact image.

No Flipper speed/range parity, universal NFC/RFID compatibility or complete
315/915 MHz over-the-air qualification is claimed by this update.
